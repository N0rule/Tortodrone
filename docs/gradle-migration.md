# Gradle migration

The Java sources and resource resolution remain in their existing directories. Gradle 9.5.1
and Shadow 9.3.2 replace shell compilation and manual dependency extraction. Both public
JAR names/main classes are unchanged; external maps/items remain beside them. No application
networking, storage schema, authentication or game logic changes are part of this migration.
`VERSION` remains 0.22.0 because this is a build migration, not a server behavioral release.

## Changed files

Added `build.gradle.kts`, `settings.gradle.kts`, `gradlew`, `gradlew.bat`,
`gradle/wrapper/gradle-wrapper.jar`, `gradle/wrapper/gradle-wrapper.properties`,
`gradle/verification-metadata.xml`, `.gitattributes` and this migration record.
Updated `.gitignore`, `README.md`, `AGENTS.md`, `docs/PROJECT.md`,
`docs/development.md`, `docs/dependencies.md`, `docs/maps.md`, `docs/game-data.md`,
`docs/town-interactions.md` and bundled `src/main/resources/THIRD-PARTY.md`.
Build support changes are in `scripts/BuildTools.java`; focused test/usage updates are in
`src/test/java/org/tortodrone/integration/{ServerIntegrationTest,MapPreparationIntegrationTest}.java`,
`src/test/java/org/tortodrone/resources/DefaultResourcesTest.java` and
`src/test/java/org/tortodrone/benchmark/LoadBenchmark.java`. Removed `Makefile` after verification.
`.gitattributes` preserves LF for the Unix Wrapper and CRLF for the Windows Wrapper.

## Dependency and resource integrity

JLine is a compile/runtime dependency using the same aggregate `jdk11` classifier as before;
SQLite JDBC is runtime-only because application code uses `java.sql`. Transitive resolution
is disabled for these two aggregate runtime JARs to preserve the previous shipped classpath
and avoid optional SSH/logging libraries. Plugin dependencies remain Gradle-managed.
Verification metadata preserves the two original artifact SHA-256 hashes and adds checksums
for plugin artifacts and resolved POM/module metadata. Newly generated plugin/metadata hashes
are initial trust pins, not an independent signature validation. Review dependency changes;
do not regenerate metadata just to bypass a verification failure.

Shadow merges service descriptors and rejects duplicate final ZIP entries. Signature files,
stale dependency indexes and module descriptors are omitted; upstream licenses and native
libraries remain. Archives have fixed timestamps and stable entry order. The Wrapper distribution
has an official SHA-256 pin; Wrapper scripts/JAR are generated by that Gradle release.

`prepareDefaults` and `prepareMaps` run the existing Java build tool, without shell commands
or runtime dependency resolution. Source maps are verified before any copy; existing files
are retained (including dangling owner-file symlinks), and absent optional source directories
warn and succeed. Present malformed sources and incomplete/corrupt supplied packs still fail preparation. Compilation
and admin packaging are independent of preparation. The runtime downloader URL/fallback are
unchanged; a missing map still prevents world entry rather than server login/admin startup.

Gradle scratch files are under `.build/gradle/`. The public `build/` tree is a deployment tree,
so `clean` removes only known generated JARs, temporary JARs, the legacy scratch subtree and Gradle's fixed `build/reports/dependency-verification/` report directory.
Do not put persistent files in either scratch subtree. Data, keys, configuration, custom maps,
prepared defaults, old dependency cache and unknown deployment files are preserved.

## Verification

Executed on Linux with Temurin JDK 25.0.4.1+1 and Gradle 9.5.1. Commands below used
`-g /tmp/tortodrone-gradle-home --no-daemon --console=plain`; cached plugin/dependency
verification was enabled normally, not bypassed.

- `make build test` before migration: compiled/packaged both applications and passed all
  49 unit programs and the build-tool download regression; then failed the server integration
  test's stale `Public key (game.publicKey):` log expectation. HEAD `d284386` had already changed
  that label. Two assertions were corrected to the current label without changing the server.
- `./gradlew build`: passed all 49 standalone unit programs and all five integration/build-tool
  programs (3m 49s). Gradle's built-in JUnit `test` action is intentionally skipped; its standalone
  dependencies execute and are the actual test suite. Packaged integration includes server startup
  with no optional defaults, offline download fallback, login/character persistence, admin operations,
  console commands, restarts and key/config/data protection.
- `./gradlew --offline integrationMaps testBuildTools prepareMaps runServer --args=--help runAdmin
  --args=--version benchmark --args='--seconds 1 --clients 2 --instances 1' --warning-mode=all`:
  passed, including preparation regressions and a two-client town benchmark (2 ready,
  2 completed, 0 failures). This is task/workflow verification, not a load-capacity claim.
- `./gradlew --offline buildServer buildAdmin --rerun-tasks --warning-mode=all`: passed, recompiling
  all production sources with release 25. A forced rebuild produced byte-identical JARs. Bytecode
  major version 69 was also checked directly.
- `./gradlew --offline unitresources_DefaultResourcesTest runServer --args=--version runAdmin
  --args=--help tasks --all --warning-mode=all`: passed after final fixture/working-directory changes.
  Source and task review found no platform-specific shell build actions or deprecated API warnings.
  `integrationMaps testBuildTools` was rerun successfully after the final absent-versus-malformed
  source distinction was added.
- Direct `java -jar build/tortodrone.jar --help` / `--version` and equivalent admin commands passed.
  ZIP inspection confirmed both main classes, native-access/multi-release manifest attributes,
  bundled version/source resources/licenses, no duplicate ZIP entries/signatures/module descriptors,
  no bundled maps, all service providers and 56 upstream native/resource files retained byte-for-byte.
  Native resources for Windows, Linux and macOS are present in both JARs.
- Disposable repository copies, including a directory name with spaces: `./gradlew --offline clean`
  preserved synthetic DB/account/config/key/default/custom-map/cache/unknown-file sentinels byte-for-byte,
  removed generated JARs/scratch/verification reports and retained an unrelated owner report. An offline
  `compileJava buildAdmin prepareDefaults prepareMaps` passed without optional map sources and preserved
  existing custom defaults. Corrupt map preparation and a deliberately mismatched JLine checksum both
  exited nonzero with diagnostics; corrupt sources created no partial deployment output.
- In a disposable copy, `runAdmin --args='--data "admin fixture/data" --list-accounts'` passed and
  created state under the repository-relative explicit path, preserving the old admin working directory.

The final resource test canonicalizes its disposable temp root and conditionally skips only symlink
assertions when the OS/filesystem denies link creation (e.g. Windows without symlink permission).
The resource test also passed when run through an aliased temporary directory:
`java --enable-native-access=ALL-UNNAMED -Djava.io.tmpdir=/tmp/tortodrone-temp-alias -cp
build/tortodrone.jar:.build/gradle/classes/java/test org.tortodrone.resources.DefaultResourcesTest`.
This simulates a path alias on Linux; it is not a macOS execution result.
Application Java code and the runtime recovery URL/fallback were not changed.

## Limits

Windows and macOS were reviewed at source/configuration level; neither OS was executed. No graphical
admin/stock-client rendering test was performed. The existing benchmark's RSS/thread sampling uses
Linux `/proc`; those metrics remain unavailable/zero on other operating systems.

A cold Wrapper distribution download was attempted and timed out at the original 10-second deadline;
actual Wrapper builds then used the locally cached official distribution. The Wrapper now has a
60-second network timeout and two retries, but a successful cold download with those settings was
not demonstrated here. Offline builds still require a cached distribution, plugins, dependency
artifacts/metadata and a local JDK 25. The full regression suite/benchmark requires the bundled map
fixtures; `buildServer`, `buildAdmin` and compilation remain available when optional map sources are
omitted. Missing runtime maps still block world entry while allowing login/local administration.

The Makefile was retained for the baseline and removed only after the Gradle packaging, regression,
preparation, run and data-preservation checks passed. No owner processes or real runtime data were
stopped, cleaned or modified; all process-starting tests used disposable deployments.
